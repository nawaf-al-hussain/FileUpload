## 1. Executive summary

1. **Exposure classification: Public asset delivery by design.** [FACT] Unauthenticated visitors can retrieve exactly the two whitelisted runtime files (`reVC.data.b33`, `gta3.img`) through the deployed Edge proxy — no credential of any kind is checked. This is the documented production-target posture accepted during B3.6 (§12.5/§12.6 of the B3.6 report listed "keep public / restrict / tear down" as an open owner decision), not an unintended leak. Everything else about the door is tight: the asset whitelist rejects every malformed/traversal/foreign name tested (12/12 negative probes → `404 {"error":"unknown asset"}`), the GitHub PAT and the ~1 h signed URLs never reach the client, no CORS read path exists, and browser-embedded cross-site hotlinking is blocked by `Cross-Origin-Resource-Policy: same-origin`. The private GitHub release itself remains private; the proxy is the one intentional public door.
2. **Runtime byte-lock: INTACT.** [FACT] All five local runtime files hash-match the known-good records exactly (`reVC.js` 554,947 B `61add4be…`, `reVC.wasm` 3,781,629 B `8e8175ea…`, `reVC_data_b33.js` 25,568 B `cf7f6a2b…`, `reVC.data.b33` 175,394,551 B `cf09a90a…`, `gta3.img` 327,487,488 B `c840a7b1…`); the staged deployment copies are identical; live HEAD sizes match; release `runtime-b35` shows 5/5 assets `uploaded` at exact sizes; worktree `wt-b35` is clean at checkpoint `7896d0d`.
3. **Ghost multiplayer: FEASIBLE, recommend proceed to a minimal prototype.** [FACT→RECOMMENDATION] The decisive prerequisite — reading the player ped's world position and heading from the production wasm heap — is **already verified in the current build**: the B3.5/B3.6 playtest telemetry read `CWorld::Players[PlayerInFocus].m_pPed` → position floats (ped+52…60) and forward vector (ped+20/24) live, in every run, on the exact byte-locked wasm (`8e8175ea…`), via the exported `HEAPU8/HEAPU32` views. Combined with free networking (WebRTC DataChannel; PeerJS free cloud broker; Cloudflare Durable Objects on the Free plan; free TURN at 20 GB/mo), a 2-player co-presence prototype requires **zero runtime modifications** and **$0 spend**. Vehicle-state extraction is the one not-yet-verified piece and is scoped out of the first milestone.

```
Browser (same-origin, no credentials)
  GET /revc/index.html ──────────────► static file in deployment bundle
                                        + vercel.json headers: COOP same-origin, COEP require-corp
  GET /  ──rewrite──► /revc/index.html (same document, same etag)
  GET /reVC.js | /reVC.wasm | /reVC_data_b33.js  (root aliases)
      ──rewrite──► /revc/<same name> ► static trio from bundle + COOP/COEP
  GET /revc/reVC.data.b33 ──rewrite──► /api/asset?f=reVC.data.b33 ─┐
  GET /revc/gta3.img      ──rewrite──► /api/asset?f=gta3.img      ─┤
  GET /reVC.data.b33 (root) ──rewrite──► /api/asset?f=…            ─┤
  GET /gta3.img (root)      ──rewrite──► /api/asset?f=…            ─┤
                                                                   ▼
                    Edge Function api/asset.js (runtime 'edge')
                      1. f = URL param → exact-match against MAP whitelist
                         (only 'reVC.data.b33' and 'gta3.img' exist) else 404 JSON
                      2. resolveSignedUrl(name): GitHub API
                         GET /repos/<REPO>/releases/tags/$ASSET_TAG   (env; not client-settable)
                         → find asset by exact name → GET …/assets/<id>
                           Accept: application/octet-stream, redirect: manual
                         → captures 302 Location (signed URL, ~60 min TTL)
                         → cached in-isolate 50 min; one re-resolve on upstream 403
                      3. fetch(signed URL) server-side → streams body back as
                         200 application/octet-stream, Cache-Control: public,
                         max-age=31536000, immutable; X-B35-Proxy: edge-stream;
                         Cross-Origin-Resource-Policy: same-origin
  POST /log ──rewrite──► /api/log → 204 (beacon sink, stateless)

- **Authentication checks:** none anywhere on this URL. **[FACT]** The `VERCEL_AUTOMATION_BYPASS_SECRET` env var is provisioned but **inert on a production target** — Vercel's deployment protection / Vercel Authentication applies to preview deployments, not production of a Hobby project. Probes confirmed: all requests without any header/cookie returned 200. **[FACT]**
- **Client input surface:** the only client-controllable value is `f`, used exclusively as a whitelist Map key. It never reaches any URL, path, or header sent upstream. `ASSET_TAG` comes from env only. **[FACT]**
- **Favicon:** `GET /favicon.ico` is still 404 as a URL **[FACT]**; the 8B-5 fix was an HTML-level `data:` icon declaration, which suppresses the *browser's* favicon request — the direct 404 is cosmetic and unreachable during normal play.
- **Error handling:** every failure path returns a JSON constant (`unknown asset`, `proxy not configured`, `origin resolution failed: <constructed-status-string>`, `origin fetch failed: <status>`) with `Cache-Control: no-store`. No stack traces, no URLs, no token material. **[FACT]**

## 6. Ghost-multiplayer technical feasibility (Phase C1/C2)

### 6.1 Smallest useful prototype (C1) — definition

**[RECOMMENDATION]** Two-player (extensible to ~4) co-presence: each player sees the others as named ghost markers in the same world, plus optional simple checkpoint races.

In scope: remote player **position + heading**; on-foot representation; join/leave presence; basic interpolation/dead-reckoning; latency handling (last-write-wins, 10–20 Hz); optional race mode (checkpoint list, local timing, broadcast progress).
Explicitly **out of scope** until a credible path is demonstrated: shared NPCs, shared traffic, synchronized collisions, missions/combat, any shared world state (each client keeps running its own local simulation — ghosts are visual overlays, not entities of the other player's world).

### 6.2 Is player state accessible? (C2) — technique matrix

**[FACT]** The build's export/introspection surface: `Module._gGameState` (data export = linear address 4478456), `Module.HEAPU8/HEAPU32/ccall/FS` (`EXPORTED_RUNTIME_METHODS`), `-g2` debug info in the wasm, and `EXPORTED_FUNCTIONS=_main,_gGameState` (plus `___set_stack_limits`). No `FindPlayer*`/`CWorld` functions are exported by name — but none are needed, because the data-layout route is already proven.

| State item | Technique | Classification |
|---|---|---|
| World/session readiness (game state) | `Module._gGameState` (u32 @ 4478456) — already read live every second by the deployed HUD/heartbeat (`gs=7` menu observed) | **Verified in the current build** |
| Player world position x,y,z | `CWorld::PlayerInFocus` u8 @ 2973762 → `CWorld::Players[focus]` base 2973776 (CPlayerInfo stride 368) → `m_pPed` u32 @ +0 → f32 @ ped+52/56/60 | **Verified in the current build** — used as engine telemetry in every B3.5/B3.6 playtest (local + 3 remote runs), responds to input; offsets "verified against the disassembly and the engine headers" |
| Heading / movement state | forward f32 @ ped+20/24 → `heading = atan2(-fx, fy)`; speed derivable from consecutive positions (turn test measured 332.6° delta live) | **Verified in the current build** |
| On-foot vs in-vehicle | `CPlayerInfo.m_pRemoteVehicle` @ +4 read live (field present, value polled); true in-vehicle flag lives in CPed fields (e.g. `m_pVehicle`) — offset not yet mined | **Supported by source evidence, not runtime-tested** |
| Vehicle identity / transform | CVehicle model index via CEntity fields; mineable with the same disassembly method used for CPad/CWorld | **Plausible but unverified** |
| Respawn / death / health state | CPed/CPlayerInfo health fields; same mining route; death also detectable as ped-pointer change + position freeze | **Plausible but unverified** |
| Direct engine-function call (e.g. `FindPlayerCoors`) | would require adding to `EXPORTED_FUNCTIONS` = **rebuild** | **Not currently feasible** under the byte-lock — and unnecessary given the data route |

**[FACT]** Provenance of the offsets: all addresses were mined from the production `reVC.wasm` itself (sha `8e8175ea…`) — `CPad::Old/New/TempKeyState` @ 2534448/2535072/2535696 via `UpdatePads` `memory.copy` analysis; `CWorld` block via disassembly + engine headers; documented in `B3.5-PLAYABLE-GAMEPLAY.md` §5 and the harness header comment. The same mining method (not new invention) is what any unverified row above would use.

**[FACT]** The read/write channel is proven in both directions on this exact build: reads (position telemetry every poll) and writes (`TempKeyState` key injection drives menu navigation and all movement tests). Ghost-MP needs **reads only**.

**Risks, as required by the brief:**
- **Unstable pointers:** `m_pPed` is a runtime heap pointer that can change on death/respawn/ped-recreation. Mitigation: re-derive focus → `m_pPed` on *every* poll (exactly what the harness does); treat `ped==0` as "no ghost data this tick".
- **Build-specific layout:** every offset is valid only for wasm `8e8175ea…`. The byte-lock makes this safe; any future rebuild invalidates the table → the MP page must check `Module._gGameState != null` and optionally gate on a canary (e.g. `TempKeyState` mirror-copy behavior) before trusting addresses.
- **WASM memory growth:** `-sALLOW_MEMORY_GROWTH=1` (initial 128 MB, max 2 GB). Growth **appends** — existing linear addresses are never relocated — so statics stay valid; `Module.HEAPU8/HEAPU32` views must be re-fetched from `Module` after growth (the harness pattern already does this implicitly by re-reading `Module.HEAPU8` each poll).
- **Data races / tearing:** page thread reads while the game's main thread writes (shared SAB). Aligned 32-bit reads are effectively safe; an occasional torn read only jitters one ghost sample and is masked by interpolation.
- **Pthreads:** pooled workers exist, but game logic and `CPad` updates run on the main thread (proven: page-side shim writes take effect through the engine's per-frame `UpdatePads` copy chain) — page-side reads observe coherent per-frame state.

```
┌─ client A (browser) ─────────────────────────┐      ┌─ room (CF DO / PeerJS) ─┐

- **Isolation by construction:** a *separate* page (`/revc-mp/index.html`) hosts MP; the existing `/revc/index.html` stays byte-identical → "single-player works identically with multiplayer disabled" holds trivially, and the five runtime files are loaded untouched by both.
- **Precedent:** page-layer augmentation on this deployment is already validated (the 8B-5 loading HUD ships in the staged page; runtime bytes untouched). Ghost-MP is the same class of change, bigger.
- **Rendering milestones:** **M1** = co-presence HUD chip per peer (name, distance, bearing arrow, on a static overlay) — needs *only* verified telemetry. **M2** = true on-screen ghost projection — requires mining `TheCamera` matrix (read-only spike, same disassembly method; plausible-unverified). **M3** = checkpoint race mode (local timing + broadcast progress).
- **Privacy/abuse:** rooms gated by a shared room secret negotiated out-of-band; no credentials, asset URLs, or signed URLs ever transit the room (acceptance test A7).
- **Fallback:** if the room/relay is unreachable, the page runs the game normally with MP silently disabled (acceptance test A8).

## 10. Go/no-go recommendation (Phase C5)

**Recommendation: PROCEED to a minimal prototype (M1), under three conditions.**

**Why proceed — [FACT]-backed:**
1. The single hardest prerequisite — reading player position/heading from the *exact* production wasm — is already **verified in the current build** by three independent runs on the deployed preview (not a lab-only result). There is no research unknown left in the critical path for M1.
2. Extraction is **read-only** through documented, exported runtime views (`HEAPU8/HEAPU32`, `_gGameState`); the byte-lock is not just preserved, it is *structurally irrelevant* to the design (no rebuild, no patch, no injection).
3. Networking has at least three genuinely free paths with no payment card; the recommended one (CF DO) additionally removes the NAT/TURN variable entirely for the prototype.
4. The deployment already carries a validated precedent for page-layer augmentation without runtime changes (8B-5 HUD).

**Conditions — [RECOMMENDATION]:**
1. **Separate MP page** (`/revc-mp/`), SP page byte-identical (A5/A6 gates automatic).
